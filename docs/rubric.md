# Evaluation rubric

Score each criterion from 0 to 2. Record the test command, the result, and the relevant output or database rows. Mark a criterion **unverified** when the available evidence supports none of the listed scores. Record what evidence is missing and label the total provisional.

| Requirement | 2 points | 1 point | 0 points |
| --- | --- | --- | --- |
| [AUTH-01. Sign in and sign out](assignment.md#auth-01-sign-in-and-sign-out) | Valid credentials establish a session. Invalid credentials and expired, missing, or revoked sessions are denied. Evidence shows that a signed-out token cannot be reused. | Sign-in and signed-out route protection work. Expiry or revocation remains unverified. | Invalid credentials establish a session, or an invalid session grants access. |
| [PERM-01. Enforce permissions on the server](assignment.md#perm-01-enforce-permissions-on-the-server) | Staff see only their own history. Direct admin actions and staff reports are denied. Evidence confirms that denied writes leave inventory unchanged. | Staff restrictions and separate history work through the interface. A direct action or stored-state check remains unverified. | A staff account reads another user's reservations, reads an admin report, or changes inventory through an admin action. |
| [INV-01. Manage available stock](assignment.md#inv-01-manage-available-stock) | Admin create and restock persist correct quantities. Invalid, duplicate, and over-limit writes leave stock unchanged. | Valid create and restock persist correctly. One or more rejected-write cases remain unverified. | A valid write loses or misstates stock, or an invalid write changes stock. |
| [RES-01. Reserve the last unit](assignment.md#res-01-reserve-the-last-unit) | The test demonstrates overlap at the reservation write. One request succeeds, the other reports out of stock, and the database contains the winner's reservation with zero stock. | The responses and persisted state match, but the evidence does not establish overlap. | Observed behavior violates any required result or persisted state. |
| [RES-02. Roll back a failed reservation](assignment.md#res-02-roll-back-a-failed-reservation) | A database insert fails, the error reaches the caller, stock stays available, no reservation persists, and a valid retry succeeds. | The test demonstrates the error, unchanged stock, and no persisted reservation. Recovery through a valid retry remains unverified. | The operation reports success, loses stock, leaves a reservation, or prevents a subsequent valid request from reserving the unit. |
| [RPT-01. Report stock and reservations](assignment.md#rpt-01-report-stock-and-reservations) | The report shows correct quantities and counts. Evidence demonstrates a Redis hit and database fallback. The page shows the source and timestamp, and reservations still use live stock. | The report totals are correct, but freshness, cache hit, or fallback evidence is incomplete. | Report totals are wrong, an unavailable cache breaks reports, or cached stock controls a reservation. |

Maximum score is 12 for the full assignment. A score of 0 on RES-01 or PERM-01 blocks acceptance regardless of the total. Judge observable behavior. Implementations may use any concurrency strategy that satisfies the requirements and can demonstrate overlap.
